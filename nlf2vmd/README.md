# nlf2vmd — NLF のモーションを MMD 用 VMD に変換する

NLF（[mp4_to_mannequin_ja.ipynb](../mp4_to_mannequin_ja.ipynb)）で抽出した SMPL のモーションを、
MikuMikuDance / MikuMikuMoving 用の VMD に変換します。仕様は [vmd.md](../vmd.md) です。

* 脚は**足ＩＫの位置キー**、体の移動は**センター（水平）／グルーブ（上下）**、上半身と腕は**回転キー**で出力します。
  脚には、足ＩＫに届いた姿勢で膝を SMPL の膝の向きに合わせた**足・ひざ・足首の回転キー**も打ちます（膝の向きを IK ソルバ任せにしない。
  [膝の向き](#膝の向き脚の回転のキー) を参照）
* 腕や脚が数フレームだけ別の位置へ飛ぶ・体の向きが一瞬反転する・骨盤が数フレームだけ浮く／沈む／前後へ飛ぶ、といった
  **明らかに間違ったフレーム**を、慣性（前後のフレームからの予測）と重力（重心の加速度が重力と床からの力で出せる範囲か）で
  見つけて、前後から置き換えます（速い腕の動き・回転・本当のジャンプは残します。[外れフレームの除外](#外れフレームの除外慣性重力) を参照）
* 接地中の足はロックし（足滑り 0）、床に埋まらないようにし、脚が伸び切らない高さまでセンターを下げます
* 単眼推定でぶれやすい奥行き（カメラの前後）は、接地している足から骨盤の奥行きを求め直します（Z 方向の足滑りを防ぐ）
* 奥行きのずれがカメラの高さ・見下ろし角のせいで上下のずれにもなり、両足が長く宙に浮いたままになる状態は、
  体全体を上下に平行移動して床に戻します（滞空 0.6 秒以下のジャンプはそのまま残します）
* 単眼推定ではカメラの前後に傾く角度がほとんど決まらず、足が床に着いたまま体全体が前後に傾くので、
  全身の重心が接地している足の上に来るように骨盤から上を起こします（重心が足の上に残るお辞儀・前傾はそのまま残します）
* 組んだ腕・交差した腕が MMD で**互いを貫通しない**ように、重なったら片方の腕（既定は左腕）を肩まわりに回し、ひじを曲げ伸ばしして離します
  （[腕どうしの貫通の防止](#腕どうしの貫通の防止) を参照）
* 処理前後の評価指標（JSON）と、判定の妥当性を確認するグラフ（PNG）を毎回出力します
* GPU も SMPL の公式ファイルも不要です（体モデルは NLF の TorchScript から書き出したものを使います）
* 動画の音声から**口パク**（口のモーフ「あ」「い」「う」「え」「お」「ん」のキー）も作れます（`lipsync.py`。
  ボーカルの分離に Demucs、音素の認識に Allosaurus を使います。[口パク](#口パクリップシンク) を参照）
* 動画から**手の形**（グー・チョキ・パー・指 1 本だけ など 9 種）を判定して、指ボーンのキーも作れます（`hands.py`・`hand_detect.py`。
  指の 21 点の推定に MediaPipe Hands を使います。[手の形](#手の形指) を参照）

## 使い方

### ノートブックから

`mp4_to_mannequin_ja.ipynb` のセル 9 で準備し、セル 10 で手を検出し、セル 11 で変換し、セル 14 で選んだ種類の VMD
（既定は `nlf_mannequin/motion_full.vmd` と、ジャンプなどによる浮きを除いた `nlf_mannequin/motion_full_locked.vmd`）を書き出します（[出力の種類](#出力の種類)）。同じフォルダに、変換の入力 `motion_for_vmd.npz`・
体モデル `smpl_body_model.npz`・手の検出結果 `hands_analysis.npz` も保存されます。

### コマンドラインから

必要なもの: Python 3.9 以上、`numpy` `scipy` `pyyaml` `matplotlib`（グラフを出す場合）。

```bash
# ノートブックが保存した入力と体モデルから変換（体モデルは同じフォルダにあれば自動で使われます）
# 既定でフル（motion.vmd）と接地優先（motion_locked.vmd）の 2 つを書き出す
python -m nlf2vmd motion_for_vmd.npz -o motion.vmd --pmx モデル.pmx

# 移動なし・上半身のみも書き出す（motion_no_move.vmd / motion_upper_body.vmd。full を外すと motion.vmd は書かない）
python -m nlf2vmd motion_for_vmd.npz -o motion.vmd --pmx モデル.pmx --variants full,locked,no_move,upper_body

# 手の検出結果も使う（手首の向きの補正と、手の形（指ボーン）のキー。指の形で腕・指と体の接触を解き直す）
python -m nlf2vmd motion_for_vmd.npz -o motion.vmd --pmx モデル.pmx --hands hands_analysis.npz

# 設定を 1 項目ずつ変える
python -m nlf2vmd motion_for_vmd.npz --pmx モデル.pmx --set center.mode=B --set scale.depth_scale=0.5

# 設定ファイルで変える（default_config.yaml をコピーして、変えたい項目だけ残す）
python -m nlf2vmd --dump-config my_config.yaml
python -m nlf2vmd motion_for_vmd.npz --pmx モデル.pmx --config my_config.yaml

# 入力なしで動作確認（合成の歩行データと簡易体モデル）
python -m nlf2vmd --demo -o demo.vmd
```

### Python から

```python
from nlf2vmd import convert

result = convert('motion_for_vmd.npz', 'motion.vmd', pmx='モデル.pmx',
                 overrides=['center.mode=B'])
print(result.metrics['foot_slide_cm_per_frame'])   # {'before': ..., 'after': ...}

# 出力の種類を選んで書き出す（convert の出力先を None にすると、convert は VMD を書かない）
from nlf2vmd import write_variant
from nlf2vmd.hands import make_hands
from nlf2vmd.lipsync import make_lipsync

from nlf2vmd.pipeline import apply_hand_poses

result = convert('motion_for_vmd.npz', None, pmx='モデル.pmx', diag_dir='vmd_diag',
                 hands_analysis='hands_analysis.npz')        # 手首の向きの補正（任意）
lip = make_lipsync('lipsync_analysis.npz', pmx='モデル.pmx')   # 口パク（任意）
hand = make_hands('hands_analysis.npz', pmx='モデル.pmx',       # 手の形（任意）
                  num_frames=len(result.contact.flags))
apply_hand_poses(result, hand.tracks)   # その指の形で、腕・指と体の接触（ステージ9b）を解き直す
write_variant(result, 'full', 'motion_full.vmd', morphs=lip.tracks, bones=hand.tracks)
write_variant(result, 'locked', 'motion_full_locked.vmd', morphs=lip.tracks, bones=hand.tracks)
write_variant(result, 'no_move', 'motion_full_no_move.vmd', morphs=lip.tracks, bones=hand.tracks)
write_variant(result, 'upper_body', 'motion_upper_body.vmd', bones=hand.tracks)
write_variant(result, 'face', 'motion_face.vmd', morphs=lip.tracks)
```

`convert` の入力は npz のパスか、同じキーを持つ dict です。

| キー | 形 | 内容 |
|---|---|---|
| `pose` | (T, 24, 3) | SMPL の関節回転（回転ベクトル）。(T, 24, 4) のクォータニオン、(T, 24, 3, 3) の回転行列も可。先頭に人物の次元があれば `input.person_index` の 1 人を使う |
| `betas` | (T, 10) か (10,) | 体型。フレーム毎なら中央値で 1 つに固定 |
| `trans` | (T, 3) | SMPL の移動量 [m] |
| `fps` | スカラー | |
| `coord_system` | 任意 | `camera`（NLF の出力: Y 下向き・Z 奥向き）か `yup`。無ければ `input.coords` の設定（既定 camera） |
| `valid` / `joints3d` | 任意 | 検出できたフレーム（False のフレームは前後から補間しただけとみなし、床・接地・奥行き・前後の傾きの推定に使わない）/ 関節位置 [mm]（体モデルの自己検証に使う） |

体モデルは `--body-model`、入力 npz 内の `bm_*` キー、入力と同じフォルダの `smpl_body_model.npz`、
smplfitter（SMPL 公式ファイル）の順に探します。

## 出力

| MMD ボーン | キー | ソース |
|---|---|---|
| センター | 位置（X, Z） | 骨盤の水平位置（ステージ8） |
| グルーブ | 位置（Y） | 骨盤の高さ（ステージ8）。グルーブが無いモデルはセンターの Y |
| 下半身 / 上半身 / 上半身2 | 回転 | 骨盤(0) / 背骨(3, 6) / 背骨(9)。上半身2 が無いモデルは上半身に合成 |
| 首 / 頭 | 回転 | 首(12) / 頭(15) |
| 左右の肩・腕・ひじ・手首 | 回転 | 鎖骨(13, 14)・肩(16, 17)・肘(18, 19)・手首(20, 21)。手首は手の検出結果で向きを補正（ステージ2b）。胴の近くの手は、胴に対する位置を保つように腕・ひじを補正（ステージ9h）。自重する側の腕は、腕どうしが重ならないように補正（ステージ9a）。腕・手のひら・指先が体・相手の腕に入らないように、腕・ひじ・手首を補正（ステージ9b） |
| 左右の腕捩・手捩 | 回転 | 腕のひねり（上腕の軸まわり）と、ひじ・手首のひねり（前腕の軸まわり）。捩りボーンのあるモデルだけ（下記） |
| 左右の足・ひざ・足首 | 回転 | 股関節から足ＩＫのターゲットまでを、モデルの脚で 2 ボーンの IK として解き、膝を SMPL の膝の向きの側に置いたもの（ステージ9l。足首は足ＩＫの回転と同じ向き）。`leg_keys.enabled: false` で打たない |
| 左足ＩＫ・右足ＩＫ | 位置＋回転 | 足首の位置と回転（ステージ7）。接地中は、足裏全体が着いている所は位置と回転を固定し、つま先だけ・かかとだけが着いている所（かかと上げ・かかとからの着地・ピボット）はその点を固定して足を回す（`foot_ik.pivot`） |

つま先ＩＫにはキーを打ちません。キーは全フレームに打ちます（`vmd.thin_keys` で間引き可）。
PMX を指定しないときは、標準的な体格（身長 20 単位前後・A ポーズ）のボーン寸法で変換します。
**実際に使うモデルの PMX を指定するのがおすすめです**（脚長とボーンの向きをモデルから読みます）。

### 出力の種類

`variants.py`（`write_variant`）で、変換結果から次の 5 種類を書き出せます。ノートブックではセル 14 で選びます（既定はフルとフル [接地優先]）。

| 種類 | `kind` | ノートブックのファイル | 内容 |
|---|---|---|---|
| フル | `full` | `motion_full.vmd` | 上の表のボーンすべて（`convert` の出力と同じ）＋口パク＋手の形（指ボーン） |
| フル [接地優先] | `locked` | `motion_full_locked.vmd` | フルから、ジャンプ・片足上げなどによる足の浮きを除いたもの＋口パク＋手の形。どのフレームでも両足を床に着ける（片足を上げる動きも、足を床に着けたまま動かす）。回転とセンターの水平移動はフルと同じ（脚の回転は、下ろした足ＩＫに届くように解き直す） |
| フル [移動なし] | `no_move` | `motion_full_no_move.vmd` | フルから体の水平移動を除いたもの＋口パク＋手の形。センターの X・Z は 0 で、足はその場で足踏みする |
| 上半身のみ | `upper_body` | `motion_upper_body.vmd` | 上半身・上半身2・首・頭・肩・腕・ひじ・手首の回転と、手の形（指ボーン）だけ。体全体の向きは除く |
| 表情のみ | `face` | `motion_face.vmd` | 口パクのモーフのキーだけ |

* **フル [接地優先]**（`locked.py`）: フルで足が床から離れている所（ジャンプとして残した区間・片足を上げた所・片足を上げたときに体ごと
  持ち上がって見える所・推定のずれで足が浮いた所）を、足を床から離さなかったものとして作り直します。
  1. ジャンプとして残した区間（ステージ6a の滞空）は、体（骨盤・足首）を床まで下ろしてから、センター（ステージ8）を求め直します
     （骨盤は跳び上がらず、上げた足は体と一緒に下りる）
  2. 足ＩＫは、どのフレームでも両足の足裏が床に着くまで、足ごとに下ろします（床より下へは下ろさない）。足裏の高さは MMD のモデルの足の形
     （足ＩＫの位置と回転で動かした、足首の真下のかかとと、つま先ＩＫの真下のつま先）で求め、最後に足裏の最も低い点をちょうど床に合わせます
     （SMPL の足の形で求めると、足首の高さ・足の長さの比がモデルと違うので、かかとを上げて足を寄せたときなどにモデルの足が数 cm 浮く）。片足を上げる動き（足踏み・蹴り・腿上げ）も、
     足は床に着いたまま（床の上を動く）になります。`locked.both_feet: false` にすると、片足だけの浮きは残し、両足とも浮いたときだけ
     低いほうの足が床に着くまで下ろします（高いほうの足も同じだけ下ろす）
  3. 足を接地判定の開始の高さ（3cm）より下ろした所では、床に下ろした足が、フルで着いていた位置（接地区間のロック位置）から
     水平に 3cm（`locked.still_m`）以内にある間は、その接地区間を延ばして床に固定します（ロック位置・回転はフルの値のまま。
     前後 2 つの接地区間がつながったときは 2 つのロック位置の間をなめらかにつなぐ）。水平に動いている足は固定せず、床の高さへ下ろすだけです

  回転（上半身・腕・下半身など。脚の 足・ひざ・足首 の回転は、足ＩＫ・センターに届くように解き直すので、足ＩＫが違うフレームでは違う）と
  センターの水平移動はどのフレームでもフルと同じで、足が浮いていた所から離れたフレームはグルーブ・足ＩＫも
  フルと同じ値になります（既定では片足を上げる所もすべて変わるので、足を上げない区間だけが同じになります）。2 つの VMD を読み込み、ジャンプを残したい所はフル、浮いて見える所は接地優先、のように切り貼りして使えます。
  書き出すときのログ「[接地優先] フルと違うフレーム: …」が、2 つの動きが違う区間です（差が 5mm・0.5 度以下のフレームは同じとみなす）
* **フル [移動なし]**: 足ＩＫの水平位置を、足ごとに「足跡のずらし量」だけずらします。足が着いている間（足跡）はずらし量が一定
  （その間のセンターの平均位置）なので、足は床を滑りません。足が浮いている間は、足が前の足跡から次の足跡へ進んだ割合だけずらし量を進めるので、
  足はその場で上下しながら次の足跡へ移ります。接地判定が 1 つの接地を 2 つに割った所（ロック位置の差が 10cm 未満）は 1 つの足跡にまとめ、
  判定が遅れた・早く切れたフレームも足が止まっていれば（3cm 以内）足跡に含めます。上下（グルーブ）はひざの曲げ・しゃがみ・ジャンプの
  高さなので残し、足をずらした脚が届く高さへのクランプだけ掛け直します（上下も除くと脚が床に届かず、足が浮きます）
* **上半身のみ**: センター・下半身にキーを打たないので、上半身の回転は大域回転になります。そこから下半身の鉛直軸まわりの向きを除くので、
  振り向いても上半身だけが回ることはなく、下半身に対するひねり・おじぎ・体の傾きは残ります。ほかのモーションのあとに追加で読み込むと、
  上半身から先だけを差し替えられます

診断出力（既定: `<VMD 名>_diag/`）:

* `diagnostics.json` — 評価指標（処理前・処理後）、接地区間、床・スケール・警告などの情報、使った設定
* `outliers.png` — 部位ごとの外れの度合い（1 がしきい値）と置き換えたフレームの帯、重心の上下・奥行きの推定と重力の条件を満たす軌道
* `contact.png` — 左右の足の高さ・水平速度と接地判定の帯
* `center.png` — センターの X・Y・Z の処理前後
* `depth.png` — 骨盤の奥行きの処理前後（接地している足から求め直した奥行き）と、入力の奥行き・横方向のぶれの大きさ
* `ground.png` — 両足の最下点の高さの処理前後、上下のずれを求めた足の高さ（緑の線: 接地している足。無ければ両足の最下点）と、接地の拘束による上下の補正量（ジャンプとして残した区間はオレンジの帯）
* `lean.png` — 足の支持点の中心から全身の重心への線の前後（カメラの奥行き方向）の傾きの処理前後と、掛けた補正角
* `arm_collision.png` — 左右の腕のカプセルの重なりの深さの処理前後と、自重する腕に掛けた補正角。下段は補正で自重する腕
  （ひじ・手首・手の先）が動いた距離の、画像面内とカメラの奥行き方向の成分
* `reach_clamp.png` — 届く高さへのクランプの補正量
* `legs.png` — 左右の膝の向き（骨盤の正面から外向き +）と曲げ、足ＩＫに届かないフレームの帯（ステージ9l）
* `foot_ik_topview.png` — 足ＩＫの水平軌跡の上面図（接地点が点になっているか）

| 指標 | 定義 | 目標 |
|---|---|---|
| 足滑り | 接地区間内の足ＩＫの水平移動量の平均（cm/フレーム） | 0 |
| 埋まり | 足ＩＫの差分Yが0未満のフレーム数 | 0 |
| 浮き | 両足の最下点が接地終了の高さより上にいる状態が、`ground.max_flight_sec`（0.6 秒）より長く続くフレーム数 | 0 |
| 短い浮き | 両足とも接地区間の外で、ジャンプとして残した区間でもないのに、出力の両足の足裏が床から 2cm より上にあるフレーム数 | 0 に近い |
| センターの震え | センター・グルーブ位置の加速度の絶対値の平均（軸別、cm/フレーム²） | 処理前より大幅に減少 |
| 姿勢の震え | 各関節の角加速度の平均（グループ別、deg/s²） | 処理前より減少 |
| 脚の伸び切り | 股関節から足ＩＫまでの距離が脚長の98%を超えるフレーム数 | 0 |
| 接地切り替え回数 | 足ごとの接地区間の数 | 目視との整合を確認 |
| 床付近の足の動き | 足が床付近にあるときの足ＩＫの移動量の平均（X, Z 別、cm/フレーム） | Z（奥行き）が X と同程度まで減少 |
| 前後の傾き | 足の支持点の中心から全身の重心への線の、カメラの奥行き方向の傾きの中央値（度） | 0 に近い |
| 腕の重なり | 左右の腕のカプセル（上腕・前腕・手）が 5mm より深く重なっているフレーム数 | 0（`arm_collision.mode: none` では処理前と同じ） |

## 外れフレームの除外（慣性・重力）

モーションキャプチャ（単眼推定）には、腕や脚が数フレームだけ別の位置へ飛ぶ・体の向きが一瞬反転する・骨盤が数フレームだけ
浮く／沈む／前後へ飛ぶ、といった明らかな誤りが混ざります。平滑化（ステージ2）の前に、次の 2 つで見つけて置き換えます
（ステージ1b。物理シミュレーションは使わず、numpy・scipy だけの軽い処理です）。

* **慣性**: 各フレームを前後のフレームから予測し（前後に当てはめた 3 次式。数フレーム続く外れのために、近いフレームを
  飛ばした予測も使う）、予測と大きく違うフレームを外れにします。部位（胴・脚・頭・左腕・右腕）ごとに、関節の位置と向きで調べます。
  しきい値はその動画の推定のぶれの大きさ（予測の差の中央値）の 6 倍で、外れのそばの正しいフレームや、本当に速く動いて止まった
  動きは外れにしません
* **重力**: 重心の加速度は、重力と床から受ける力（押すだけで引けない・摩擦の範囲・体重の数倍まで）だけで出せる範囲に入ります。
  この範囲に入る重心の軌道のうち推定に最も近いものを求め（外れに強い最適化: 候補を除き、Huber の重みで解き直す）、
  それから大きく離れるフレームを外れにします。数フレームだけ浮く・沈む・前後へ飛ぶ骨盤は外れになり、本当のジャンプ
  （重力だけで動く放物線）は残ります

置き換えは、外れた部位の関節の回転を前後から補間し、骨盤の位置は重力の条件を満たす軌道へ置き直します。胴・脚・重心が外れた
フレームは、床・接地・奥行き・前後の傾きの推定に使いません（検出できなかったフレームと同じ扱い。ただしジャンプの判定には使います）。

* ログの `[1b]` と `diagnostics.json` の `info.outliers`（部位ごとの置き換えたフレーム数・区間）、`outliers.png` で確認できます
* 0.5 秒（`outliers.max_run_sec`）より長く続く外れは、前後どちらが正しいのか決められないので置き換えず、警告します
* 外れが 15%（`outliers.max_ratio`）を超える検出は、動画に合っていない（カメラが動いている・人に持ち上げられる等）とみなして使わず、警告します
* 見つけられないもの: なめらかに間違っている区間（左右の脚の取り違えが続く・隠れた腕がゆっくり違う位置へずれる）と、
  0.3 秒ほどより長い外れ。推定のぶれ（しきい値の 1/6 ほど）に近い小さな外れ

## 膝の向き（脚の回転のキー）

MMD の脚は足ＩＫで決まります。足先と骨盤の位置は伝わりますが、膝がどちらを向くか（内股・がに股・膝を寄せる振り付け）は
股関節から足首までの軸まわりに自由で、足・ひざにキーが無いと IK ソルバの解き方しだいになります。MMD / MMM の IK は
リンクボーン（足・ひざ）のその時の回転（キーの値）から解き始めるので、ステージ9l（`legs.py`）で、**足ＩＫにすでに届いていて、
膝が SMPL の膝の向きを向いた** 足・ひざ・足首 の回転をキーにします（IK はほとんど動かさず、膝の向きが残ります。
効き方は IK ソルバしだいなので、使うモデルで確かめてください）。足の位置・接地のロックは今までどおり足ＩＫで決まります。

* **膝の向き**: SMPL の膝は太ももの X 軸（股関節の大域回転で回した X 軸）まわりに曲がるので、その軸を 股関節 → 足首 の線に
  垂直にしたものを ひざ の曲げの軸にします（MMD の ひざ も X 軸まわりに曲がるので、曲げの軸を SMPL にそろえる）。まっすぐな脚でも
  決まります。膝の位置の「股関節 → 足首 の線からのずれの向き」は使いません（SMPL の初期姿勢の膝はその線より 2cm ほど外にあるので、
  前後に曲げただけでも外を向いて見え、曲げ 20 度で 16 度、45〜90 度で 8 度ほどのがに股になる）。太もものひねりは単眼推定で
  いちばん決まりにくいので、骨盤の座標系で見た膝の向きをゼロ位相の One Euro（3Hz・beta 4。`leg_keys.pole_one_euro`）で
  ならします（フレームごとの震えが半分ほどになる。体ごと回る動きはならさない。2Hz・±20 度の膝の内外の振りは 9 割ほど残る）
* **解き方**: 股関節（センター・グルーブ・下半身の回転で動かした足ボーンの位置）から足ＩＫのターゲットまでを、モデルの脚
  （足 → ひざ → 足首 の初期位置。初期姿勢の膝の曲がりも含める）で解きます。ひざは MMD の ひざ の角度制限と同じく、ローカルの
  X 軸まわりに後ろへ曲げる向きだけに回します（初期姿勢から 0.5 度以上。届かなければ伸ばせる所まで）。足は、太もも → 足首 の
  向きをターゲットへ、ひざ の曲げの軸を「股関節 → ターゲット」と膝の向きが作る面の法線へ合わせる回転です。足首は足ＩＫの回転と
  同じ向き（`leg_keys.ankle`。つま先ＩＫの IK も届いた状態から始まり、足先の左右の傾きも SMPL に合う）
* 出力の種類（フル・接地優先・移動なし）ごとにセンター・足ＩＫが違うので、キーを作るとき（`pipeline.build_tracks`）に種類ごとに解き直します
  （膝の向きはどの種類も同じ）。上半身のみには打ちません
* ステージ9b（腕・指と体の接触）は、フルの脚の回転で脚の当たり判定を作ります（MMD で表示される脚と同じ位置）
* ログの `[9l]`・`diagnostics.json` の `info.legs`（膝の向きの 5・50・95 パーセンタイル、足ＩＫに届かないフレーム数）・`legs.png` で確認できます

## 胴に対する手の位置（体の比率の違いの補正）

腕は回転のコピーなので、肩幅・腕の長さ・胴の厚みの比が SMPL と MMD モデルで違うと、胴に対する手の位置が変わります
（SMPL で「腰に手を当てる」「胸の前で手を合わせる」動きが、MMD では手が胴に入り込むか届かない。肩幅が狭く腕が長い
モデルでは、胸の前で合わせた両手が交差する）。ステージ9h（`hand_reach.py`）で、手首が胴の近くにあるフレームだけ、
**SMPL の胴に対する手首の位置を、MMD の胴の同じ所へ移します**。

* **移し方**: 手首の位置を胸（背骨3 / `上半身2`）の座標系で表し、左右は肩幅・上下は股関節から肩までの高さ・前後は胸の
  厚みの比で MMD の胴へ移します。胸の厚みは、SMPL は体モデルの頂点、MMD は 9b と同じ体の形（剛体 → メッシュ →
  標準の形。胸などの物理の剛体は除く）から測ります
* **2 ボーン IK**: MMD の標準のモデルには腕の IK が無いので、変換の中で解いて、`腕`・`ひじ`・`手首` の回転のキーに
  します（どのモデルでも同じに再生されます）。ひじの曲げと肩の向きを変え、**手首の向き（手のひらの向き）は変えません**
* **胴から遠い手・まっすぐな腕はそのまま**: 手首が胴から 10〜25cm（`near_m`〜`far_m`）で回転のコピーへ戻し、ひじの曲げが
  20〜45 度（`bend_deg`）より小さい腕（下ろした腕・広げた腕）も回転のコピーのままにします（腕の向きを保つ）
* 補正は肩・ひじとも `max_deg`（45 度）まで。残った入り込みは次のステージ9b が離します
* 全フレームをまとめて解くので、このステージの処理時間は 10 分の動画でも約 0.2 秒です。胴に入り込んでいた手は 9b で
  離す量が減るので、変換全体はかえって速くなることが多いです（両手を合わせたまま動く場面では、9b が触れている手を
  解く分だけ遅くなります）
* `hand_reach.png` に、左右の手の重み・手首の移動量・肩とひじの補正角と、胴の寸法の比を出します。
  `hand_reach.enabled: false` で今までの回転のコピーに戻せます

## 腕どうしの貫通の防止

回転をコピーしただけでは、組んだ腕・胸の前で交差させた腕が MMD で互いを貫通します（MMD モデルは SMPL と腕の長さ・
肩幅・太さが違い、単眼推定では重なって写った腕どうしの前後の距離もぶれるため）。ステージ9a（`arm_collision.py`）で、
左右の腕が重なったフレームだけ、**片方の腕の動きを自重させて**（肩まわりに回し、ひじを曲げ伸ばしして）離します。

| `arm_collision.mode` | 動き |
|---|---|
| `left`（既定） | **左腕の動きを自重する**: 重なったら左腕をずらす（右腕は推定のまま） |
| `right` | **右腕の動きを自重する**: 重なったら右腕をずらす（左腕は推定のまま） |
| `none` | **何もしない**（貫通したまま。評価指標とグラフで重なりは確認できる） |

* 左右の腕を、上腕（腕→ひじ）・前腕（ひじ→手首）・手（手首→指先）の 3 本のカプセル（線分＋半径）で表します。
  半径は PMX のメッシュ（ウェイトが最も大きいボーンが腕・ひじ・手首とその子の頂点）の、骨からの距離の中央値です。
  手の長さもメッシュから測ります。PMX を指定しないときは `fallback_radius_m`・`hand_length_m` を使います
* 自重する腕は、**肩の関節（腕ボーンの位置）まわりの回転**と、**ひじの曲げ伸ばし**（ひじの軸まわりの 1 自由度）で動かします。
  手首の向き（手首のローカル回転）は変えません。キーが変わるのは自重する側の `左腕`・`左ひじ`（または `右腕`・`右ひじ`）
  ボーンだけです。`elbow: false` にすると肩まわりに回すだけになります（以前の動き）
    - 肩とひじのどちらをどれだけ使うかは、腕の点（ひじ・手首・手の先）の動きが最も小さくなるように決まります。肩だけでは、
      肩より前にある前腕を前後へ動かすと、肩を中心とした球面に沿って上下・左右にも動きますが、ひじも使うと、ひじ・手首・
      手の先を画像上の位置に近いまま前後へずらせます（胸の前で交差させた腕・腕組みで、手の先の画像面内の動きが約半分に）
    - ひじの補正は ±`elbow_max_deg`（30 度）まで。曲げ角（0 = まっすぐ）は 0〜150 度に収めます（まっすぐより先へは伸ばさず、
      曲げすぎない。推定の姿勢がすでにその外なら、それ以上外へは動かしません）
    - 判定は、ステージ9h（胴に対する手の位置）で直した後の腕の姿勢で行います
* 1 フレームずつ順に、前のフレームの補正から続けて、補正をなるべく 0（推定の姿勢）に戻しながら、どの組のカプセルも
  重ならない補正（肩の回転とひじの曲げ）を求めます。相手の腕が来れば押しのけられ、離れれば推定の姿勢に戻ります（戻る速さは
  `return_deg_per_s` まで）。前のフレームから続けて動かすので、**推定の腕が相手の腕を通り抜けても、自重する腕は来た側に
  留まります**（重なって写った腕の前後を単眼推定が取り違えても、通り抜けない）
* **奥行き優先**（`depth_cost`、既定 0.5）: 単眼推定では、画像面内（上下左右）の腕の位置は動画に写ったとおりで確かですが、
  カメラの奥行き方向の位置はぶれます。そこで、腕（ひじ・手首・手の先）をカメラの奥行き方向へずらす動きを安く見積もり
  （0.5 なら奥行きへ 2cm ずらすのと画像面内へ 1cm ずらすのが同じコスト）、画像面内の動きを自重して前後へずらします。
  離す向きも、最近点を結ぶ向きだけでなく、そこから奥行きの軸までの間で最も安く離せる向きを選ぶので、画像上で上下・左右に
  並んで重なった腕も前後へずらして離せます。どちらの腕が手前かは推定のまま（重なって写った腕の前後は、どちらが隠れて
  いるかで動画から分かるため）。`1` にすると向きを区別せず、最近点を結ぶ向きへ最短でずらします（以前の動き）
    - `elbow: false`（肩まわりに回すだけ）では、純粋に前後だけへはずらせません（肩より前にある前腕を前後へ動かすと、肩を
      中心とした球面に沿って上下・左右にも動く）。胸の前で組んだ・交差させた腕では、画像面内の動きが 1 割前後減る程度です
    - 画像面内と奥行きの動きは 1 つのコストで同時に決めるので、どちらか一方だけへずらすのではなく、奥行きを主に画像面内にも
      少しずつ動かします（`depth_cost` を下げるほど奥行きの割合が連続的に増えます）
    - 奥行きを優先して `max_deg` に達しても離れないフレームは、そのフレームだけ `depth_cost` を 1 へ向けて、離れるところまで
      弱めます（画像面内の動きを必要な分だけ増やす。奥行きに頼りすぎて離しきれない、ということは起きません）。弱めたフレームの数は
      ログと `info.arm_collision.relaxed_frames` に出ます
    - 補正で自重する腕が動いた量は、ログ（`腕の移動 最大 画像面内 … cm・奥行き … cm`）・`arm_collision.png` の下段・
      `diagnostics.json` の `info.arm_collision.max_shift_cm` で確認できます
* 押しのけるのに肩を `max_deg`（45 度）より大きく回す必要があるとき（推定の腕が相手の腕を大きく通り抜けた等）は、上限で止めて、
  その重なりは離れるまで扱いません（はね戻らずに少しずつ通り抜けます）。相手の手が肩のすぐ近くに触れている重なりは、
  肩まわりに回しても離せないので扱いません
* 補正（肩の回転・ひじの曲げ）を時間方向にならしてから（`smooth_sec`）、ならして浅くなった重なりをもう一度離します
* フル・フル [接地優先]・フル [移動なし]・上半身のみのどの VMD にも、補正した腕の回転が入ります
* 腕と体（胴・頭）・指先の貫通は、次のステージ9b で扱います（`mode: none` なら 9b でも腕どうしは判定しません）

## 腕・手のひら・指先と体の接触（指先までの当たり判定）

MMD モデルは服・胸・髪・スカートのぶん SMPL より体が大きく、腕の長さ・肩幅の比も違うので、回転をコピーしただけでは
手や指先が胴・胸・スカートに入り込みます。ステージ9b（`contacts.py`）で、重なったフレームだけ腕を直します。

* **腕の形**: 上腕・前腕・手のひら（手首→人指１、手首→小指１、人指１→小指１ の 3 本）・5 本の指の各節（指先まで）の、
  片腕で最大 20 本のカプセル。指先は `〇〇先` のボーン → 表示先 → 頂点の順に求め、太さは PMX のメッシュから測ります。
  指の形は手の形のキー（`hands.py`）を毎フレームに展開したもの（無ければ初期姿勢の指）
* **体の形**（`contacts.body_source`）: PMX の**剛体**（モデルの作者が置いた当たり判定）。スカート・胸などの物理の剛体は
  重なりの半分だけ離し（残りは MMD の物理に任せる）、腕・髪の剛体は使いません。剛体が無ければメッシュの頂点、
  それも無ければ肩幅・腰幅から作った標準の形。剛体には服の厚み（`cloth_margin_m`、既定 1cm）を足します
* **直し方**: 手首 → ひじ → 肩 の順に動かしやすくして（関節から先の長さで重み付け）、表面どうしが触れる所まで離します。
  指先が胸に触れただけなら主に手首、前腕が入り込んでいればひじ、上腕なら肩で直します。触れているだけの所は離さず、
  推定の手が胸を通り抜けても、手は胸の前に留まります（前のフレームから続けて動かすため）
* 腕どうしの組（指先と相手の腕を含む）は、自重する腕の肩だけで離します（大きな重なりはステージ9a で肩とひじを使って離してあり、
  ここでは指先などの残りだけを扱う）
* **判定する部位**（`contacts.body_parts`）: 当たり判定が厳しすぎて腕の動きが抑えられる・処理が遅いときは、部位ごとに
  判定を外せます（既定はすべて `true` で、これまでと同じ結果）。外した部位の組は計算しないので、その部位の近くの腕は推定の
  まま動き、処理も速くなります。腕どうしは `arm_collision.mode`（`none` で判定しない）

  | キー | 部位 | 対象の剛体 |
  |---|---|---|
  | `clothes` | 服・装飾 | スカート・ネクタイ・リボンなど、胴の骨格（上半身・上半身2・下半身など）以外のボーンに付いた剛体と、胸以外の物理の剛体（名前に スカート などを含む剛体は、胴の骨格に付いていても服・装飾） |
  | `head` | 頭部（頭から首まで） | 首・頭と、そこに付いた剛体（髪の根元・帽子など） |
  | `torso` | 胴部（首元・肩からお尻まで） | 胴の骨格のボーンに付いたボーン追従の剛体 |
  | `chest` | 胸（おっぱい） | 名前に 胸・乳・おっぱい を含むボーン（左胸・胸親など）に付いた剛体と、左胸・右胸 などの名前の剛体 |
  | `legs` | 脚（太もも） | 足・ひざ（足D・ひざD）とその子に付いた剛体 |

  剛体の無いモデル（メッシュ・標準の形）では、胸・服は胴部に含まれます。例: `--set contacts.body_parts.clothes=false`
* 手の形のキーを作ったあとに `pipeline.apply_hand_poses(result, hands.tracks)` を呼ぶと、その指の形で解き直して
  キーを作り直します（ノートブックのセル 13 が呼びます）
* 結果は `vmd_diag/contacts.png`（腕ごと・部位ごとの重なりの深さの処理前後と、肩・ひじ・手首の補正角）

## 手首の可動域

推定（手のひらの表裏の取り違え等）や接触の補正で、前腕の下側に手の甲が来るなど、人の関節では届かない向きになることが
あります。ステージ9c（`wrist_limits.py`）で、前腕のひねり（回内・回外 = ひじ と 手首 の前腕の軸まわりのひねりの和）と
手首の曲げ（掌屈・背屈・橈屈・尺屈）を、設定 `wrist_limits` の範囲（既定は日本整形外科学会の参考可動域: 回内・回外 90・
掌屈 90・背屈 70・橈屈 25・尺屈 55 度）に収めます。9b の前と後に掛け、変えるのは 手首 の回転だけです。
推定が 180 度の近くでぶれても上限と下限の間を行き来せず、範囲に収めた角の変わる速さは 720 度/秒まで
（`max_speed_deg_per_s`）。手の検出結果で手首を補正するステージ2b も、可動域から大きく外れる向きは使いません。

## 手首の向きの補正（MediaPipe の手のひらの向きから）

`convert(..., hands_analysis=...)`（コマンドラインでは `--hands`）で手の検出結果を渡すと、ステージ2b（`wrist.py`）で
手首の向きを MediaPipe の手のひらの向きへ寄せます。

* MediaPipe の 3D の点は、切り出した画像（ROI）の座標系のままなので、ROI の回転角だけ画像の面内に回し戻し、
  ROI の中心を通る視線の分の回転を掛けてカメラ座標に直します。そこから手のひらの座標系（手首・人差し指と小指の付け根）を作り、
  SMPL の初期姿勢の手のひらを重ねる回転を、手首の大域回転の目標にします
* 使うのは、手の存在スコアが高く、画像上の点と向きがそろい、前腕に対して関節として無理のない向きのフレームだけ。
  見える・見えないの境目は 0.1 秒かけて混ぜ、見えない区間は NLF の向きのままにします
* 結果は `vmd_diag/wrist.png`（NLF と MediaPipe の手のひらの向きの差・掛けた補正・重み）。差がほとんど 45 度未満なら、
  NLF の手首の向きはもともと合っています

## 口パク（リップシンク）

ノートブックのセル 12 が、動画の音声から母音を取り出します。

1. [Demucs](https://github.com/adefossez/demucs)（`htdemucs`）で音声からボーカルだけを取り出す（伴奏が混ざると音素の認識が崩れるため）
2. [Allosaurus](https://github.com/xinjli/allosaurus) でボーカルの音素（IPA）とその時刻を認識する。
   言語を `jpn` にすると日本語の音素だけで認識するので、母音がそのまま「あいうえお」に分かれる
3. 認識結果（音素と時刻）とボーカルの音量を `lipsync_analysis.npz` に保存する

セル 12a（または下のコマンド）が、`lipsync.py` で口のモーフのキーにします（ノートブックでは、セル 14 で選んだフル・フル [接地優先]・
フル [移動なし]・表情のみの VMD に入れます）。

* 母音はあ・い・う・え・お（IPA の母音を近い日本語の母音へ。唇を丸める母音は う・お へ）、両唇音 m・b・p と撥音 ɴ は ん（口を閉じる）。
  子音は形を持たず、すぐ後の母音の形を子音の時刻から始める（日本語の子音は次の母音の口の形のまま発音されるため）
* Allosaurus の時刻は音素が鳴り始める 1 点（30ms 刻み）だけで、長さは分からない。口を開けている長さはボーカルの音量から決める。
  声の区間は 2 つのしきい値のヒステリシスで判定し、しきい値は「大きな声からの差」と「雑音（Demucs で残った伴奏）からの差」の
  大きいほうにする（分離で残った伴奏を声と取り違えないため）。声が出ていない間はどのモーフも 0 で、無音の所で認識された音素は使わない
* 母音のモーフの値は声の大きさで変える（小さな声で `min_open`、大きな声で 1 × `strength`）。ん は `closed_weight` で一定。
  声が出ているのに ん が `max_closed_sec` より長く続くとき（ɴ の誤認識）は、直前の母音に戻す
* ガウシアンでならしてからフレームごとに平均し、線形補間との差が `thin_tolerance` 以内のキーは省く

```bash
# 保存した認識結果から、口パクだけの VMD と、体の動き＋口パクの VMD を作る（GPU・Demucs・Allosaurus 不要）
python -m nlf2vmd.lipsync lipsync_analysis.npz -o lipsync.vmd --merge motion.vmd --pmx モデル.pmx --plot lipsync.png

# 設定を変える（モーフ名・口の開き・声の区間のしきい値など。default_config.yaml の lipsync）
python -m nlf2vmd.lipsync lipsync_analysis.npz --merge motion.vmd --set lipsync.morphs.u=ω --set lipsync.strength=0.8
```

| 出力 | 内容 |
|---|---|
| `lipsync.vmd` | 口のモーフのキーだけ。体のモーションを読み込んだあと、フレーム 0 で追加で読み込む |
| `motion_lipsync.vmd`（`--merge` の出力） | 体の動きの VMD のボーンのキーはそのままに、口のモーフのキーを入れたもの（同じ名前のモーフのキーだけ置き換え、まばたきなどほかのモーフのキーは残す） |
| `lipsync.png` | 上: ボーカルの音量・声の区間（緑）・認識した音素（縦線）、下: 各モーフの値 |

PMX を指定すると、モデルに無いモーフ名は警告を出してキーを打ちません（`lipsync.morphs.*` でモーフ名を変えられます）。

| 症状 | 調整する設定 |
|---|---|
| 間奏・伴奏でも口が動く | `lipsync.on_above_noise_db`・`lipsync.off_above_noise_db` を大きく |
| 小さな声で口が動かない | `lipsync.voice_on_db`・`lipsync.on_above_noise_db` を小さく |
| 口の動きが声より早い / 遅い | `lipsync.lead_sec` を小さく / 大きく |
| 口がパクパクしすぎる / 鈍い | `lipsync.smooth_sec` を大きく / 小さく |
| 口がよく閉じる（ん が多い） | `lipsync.morphs.n: ''`（ん を使わない）か `lipsync.closed_weight` を小さく |

## 手の形（指）

ノートブックのセル 10 が、動画から左右の手の指の 21 点を求めます（`hand_detect.py`）。

1. NLF の手首と手先の関節（VMD の変換のステージ 1b・2 と同じ外れフレームの除外・ジッター制御を、動画の fps のまま掛けたもの。
   `pipeline.prepare` → `hand_detect.prepared_joints`）を画像に投影し、手首のまわりを MediaPipe と同じ形（手首→指の付け根が上を向く正方形）に切り出す。
   `prepare` の結果は `convert(..., prepared=...)` に渡すと変換でもそのまま使う（入力・体モデル・関係する設定が同じときだけ。違えば変換が求め直す）
2. [MediaPipe Hands](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker) の `hand_landmarker.task` に入っている
   ランドマークモデル（`hand_landmarks_detector.tflite`）に、[LiteRT](https://ai.google.dev/edge/litert)（`ai-edge-litert`）で直接入れる。
   1 回目の結果から MediaPipe のトラッキングと同じ方法で切り出しを作り直し、もう一度推定する
3. 検出結果（画像上の 21 点・3D の 21 点・手の存在スコア）を `hands_analysis.npz` に保存する

MediaPipe の HandLandmarker は、最初に画像全体から手のひらを探します。ダンス動画の手は小さく（数十 px）ぶれているので、
これでは手がほとんど見つかりません（640px の動画の 30 秒で 1〜2 割）。体の関節から手の位置を決めてランドマークモデルに
直接入れると、手が写っているフレームのほぼすべて（同じ動画で約 4 割。残りは袖・体に隠れた手）で推定できます。
存在スコアの低い手と、体の手首から離れた所に見つかった手（もう一方の手など）は使いません。

セル 13（または下のコマンド）が、`hands.py` で指ボーンのキーにします（ノートブックでは、セル 14 で選んだフル・フル [接地優先]・
フル [移動なし]・上半身のみの VMD に入れます）。

* **指ごとの判定**: 人差し指〜小指は付け根・第 2・第 3 関節の曲げ角の和（手首→付け根の向きに対する角度から）で、
  `extended_below_deg` より小さいほど「伸び」、`curled_above_deg` より大きいほど「曲げ」、間は「中間」（軽く曲げた指）の確率にする。
  親指は、MCP・IP の曲げが小さく、かつ指先が人差し指・中指の付け根側から離れているほど「伸び」（握った手の上に添えた親指を伸びとしない）。
  曲げ角は画像上の点（＋奥行き）で測る（小さく写った手では、3D の点より画像上の点のほうが見た目と合う）
* **手の形**: 次の 9 種。指のパターン（伸び / 曲げ / どちらでもよい）に合う度合いを、指ごとの確率の幾何平均で点にする。
  デフォルトは一定の点 `default_score` で、どの形にもはっきり当てはまらない手（中間の指がある手など）はデフォルトになる

| 形 | `SHAPES` | 親指・人差し指・中指・薬指・小指 |
|---|---|---|
| デフォルト | `default` | 軽く曲げる（ほかの形に当てはまらないとき） |
| 親指だけ | `thumb` | 伸び・曲げ・曲げ・曲げ・曲げ |
| 人差し指だけ | `index` | どちらでも・伸び・曲げ・曲げ・曲げ |
| 中指だけ | `middle` | どちらでも・曲げ・伸び・曲げ・曲げ |
| 薬指だけ | `ring` | どちらでも・曲げ・曲げ・伸び・曲げ |
| 小指だけ | `pinky` | どちらでも・曲げ・曲げ・曲げ・伸び |
| グー | `fist` | 曲げ・曲げ・曲げ・曲げ・曲げ |
| チョキ | `scissors` | どちらでも・伸び・伸び・曲げ・曲げ（人差し指と中指を開く） |
| パー | `open` | どちらでも・伸び・伸び・伸び・伸び（指を開く） |

  （親指の判定がいちばん不安定なので、親指が形を決める 親指だけ・グー 以外では親指を見ない）
* **時間方向**: 1 フレームごとのランドマークは、小さく写った手では大きくぶれる（同じ手の指の曲げが 1 フレームで 150 度変わることもある）。
  そこで形の点を、手の見えているフレームだけでガウシアン（`smooth_sec`）でならし、形を切り替えるたびに `switch_cost` を引いたときに
  全体で点（対数）の和がいちばん大きい形の並びを選ぶ（Viterbi）。はっきりした変化はすぐに、あいまいな変化は長く続いたときだけ切り替わる。
  手が `max_gap_sec` より長く見えない区間はデフォルト（`missing_shape: hold` なら直前の形のまま）にし、`min_hold_sec` より短く続く形は
  前後の形にまとめる。フレームレートが違えば、時刻がいちばん近い検出のフレームの形を使う
* **指ボーンのキー**: 形ごとの指の状態（`presets`: open / straight / relaxed / curled）と、状態ごとの関節の角度（`angles`: 付け根・第 2・
  第 3 関節の曲げと、付け根の開き）から、指ボーン（`bones`: 親指０〜２、人指・中指・薬指・小指の１〜３）のローカル回転を作る。
  曲げの軸は、手首・人指１・小指１の位置から求めた手のひらの法線と、各指ボーンの向き（次のボーンか表示先への向き）に垂直な軸で、
  + の角度で指先が手のひら側へ動く。親指は手のひら側と小指側の間へ曲げる（`thumb_across`）。開きは手のひらの面内の回転（+ で親指側）。
  ボーンの位置だけから求めるので、モデルのローカル軸の設定に依らない。左右は鏡像になる
* キーは形が変わる所だけに打つ。形が変わるフレームを中心に `transition_sec` かけて切り替え、始まりに前の形、終わりに次の形のキーを
  打つ（終わりのキーの補間はイーズイン・アウト）。前後の形が短いときは、その長さの半分までに縮める
* 判定した形は、区間を指定して手で直せる（`HAND_EDITS` / `--edit "12.0-13.5 右 チョキ"` / `make_hands(..., edits=[(12.0, 13.5, 'right', 'scissors')])`）。
  `HandsResult.segments(手)` が判定した形の区間の一覧

```bash
# 保存した検出結果から、指だけの VMD と、体の動き＋指の VMD を作る（GPU・MediaPipe 不要）
python -m nlf2vmd.hands hands_analysis.npz --pmx モデル.pmx -o hands.vmd --merge motion_full.vmd --plot hands.png

# 設定を変える・形を手で直す（default_config.yaml の hands）
python -m nlf2vmd.hands hands_analysis.npz --pmx モデル.pmx --merge motion_full.vmd \
    --set hands.switch_cost=5 --set hands.sides=right --edit "12.0-13.5 右 チョキ"
```

| 出力 | 内容 |
|---|---|
| `hands.vmd` | 指ボーンのキーだけ。体のモーションを読み込んだあと、フレーム 0 で追加で読み込む |
| `motion_full_hands.vmd`（`--merge` の出力） | 体の動きの VMD に指ボーンのキーを入れたもの（同じ名前のボーンのキーだけ置き換え、ほかのボーン・モーフ・カメラのキーは残す） |
| `hands.png` | 左手・右手それぞれ: 上の帯 = 判定した形、線 = 指ごとの伸び（実線）・曲げ（点線）の確率（ならしたもの）、灰色 = 手が見えないフレーム |

PMX が必要です（指ボーンの位置から曲げの軸を求めます）。モデルに無い指ボーンは警告を出してキーを打ちません
（手首・人指１・小指１が無い手はキーを打ちません。`hands.bones` でボーン名を変えられます）。

| 症状 | 調整する設定 |
|---|---|
| 手の形がすぐ変わる / ちらつく | `hands.switch_cost`・`hands.min_hold_sec` を大きく |
| 手の形の変化が遅い・短い動きを拾わない | `hands.switch_cost`・`hands.min_hold_sec` を小さく |
| デフォルトばかりになる | `hands.default_score` を小さく（0.3〜0.4）。`hands.png` が灰色ばかりなら手が見えていない（ノートブックのセル 10 の `HAND_ROI_M`） |
| 軽く曲げた手がグー・パーになる | `hands.default_score` を大きく、`hands.softness_deg` を大きく |
| 握り方・開き方がモデルに合わない | `hands.angles`・`hands.thumb_across` |

## 設定

既定値はすべて [default_config.yaml](default_config.yaml) にあり（説明付き）、設定ファイルか `--set` で上書きします。
長さのしきい値はメートルで書き、ステージ5以降は内部でスケール係数を掛けて使います。
存在しない項目を書くとエラーになります（タイプミス防止）。

MMD で見て問題があったときの調整の目安:

| 症状 | 調整する設定 |
|---|---|
| 体が後ろを向く・進行方向が逆 | `floor.flip_facing: true` |
| 足が滑る・接地のタイミングがずれる | `contact.png` を見て `contact.*` のしきい値 |
| 足が前後（Z）にだけ滑る | `depth.png` と `diagnostics.json` の `info.depth.root_jitter_cm`（奥行きのぶれ）を確認。`depth.contact_sigma_m` を小さく・`depth.prior_sigma_m` を大きく（接地足をより優先） |
| 歩いた距離（前後）が動画と合わない | `depth.prior_sigma_m` を小さく（推定された奥行きの移動に近づける） |
| 足が浮く・埋まる | `ground.png`（オレンジ = ジャンプとして残した区間、赤 = 短い浮き）と `diagnostics.json` の `info.ground.jumps_sec`（ジャンプとして残した区間 [秒]。動画のジャンプと合っているか）・`info.floor`（`tilt_deg` がカメラの見下ろし角と合っているか） |
| 本物のジャンプが床に押し付けられる | `info.ground.jumps_sec` に入っていなければ `ground.flight_accel_g` の下限を小さく（0.3 など）、`ground.min_flight_sec` を小さく。0.6 秒より長い滞空なら `ground.max_flight_sec` を大きく |
| ジャンプしていないのに体が浮く（オレンジの帯が多い） | `ground.flight_accel_g` の下限を大きく（0.7 など） |
| 座る・寝転ぶ動きでお尻が床に埋まる | `ground.enabled: false`（両足が長く床から離れる動きは浮きとみなして床に戻すため） |
| 体全体が前後（カメラの奥行き方向）に傾いている | `lean.png`（重心の傾きの線が 0 付近か）と `diagnostics.json` の `info.lean.correction_deg`（補正角）。補正がゆっくり揺れるなら `lean.window_sec` を大きく（0 でシーケンス全体で 1 つの角度） |
| 座る・寄りかかる・重い物を持つ動きで上半身が不自然に起きる | `lean.enabled: false`（重心が足の上に無い動きなので） |
| 体全体が左右に傾いている・足の裏が床と平行でない | `info.floor` の `tilt_deg`・`tilt_mode`。うまくいかなければ `floor.tilt_method: plane`（従来の方法）や `floor.align_tilt: false` と比べる |
| センターが前後にふらつく | `depth.accel_sigma_m_per_s2` を小さく、`center.axis_one_euro.z.min_cutoff` を小さく、`center.mode: B`（`scale.depth_scale` は、接地中の前後の動きを足から求め直すので効きが弱い） |
| 膝が伸び切る・暴れる | `center.reach_ratio`（0.95 など） |
| 膝の向き（内股・がに股）が動画と違う・膝が急にひっくり返る | `legs.png`（膝の向き・曲げ）。膝の向きは SMPL の太もものひねり（膝の曲げの軸）から決まるので、動画と違うときは推定そのものが違う所（`NUM_AUG` を上げると減る）。脚全体のひねりが細かく揺れるなら `leg_keys.pole_one_euro.min_cutoff` を小さく（2 など）。IK ソルバとの相性が悪いモデルは `leg_keys.enabled: false`（膝の向きは IK 任せ） |
| 足先の向きが変わらない | PMX に `左つま先ＩＫ` / `右つま先ＩＫ` があるか確認（足ＩＫの回転はつま先ＩＫを通して足首に伝わる） |
| 左右の腕が貫通する | `arm_collision.png` と `diagnostics.json` の `info.arm_collision`（`radius_cm`: 求めた腕の半径、`overlap_frames`: 重なったフレーム数）を確認。袖などが重なるなら `arm_collision.radius_scale` を大きく（1.3 など）。処理後も重なりが残るのは、補正が `max_deg` に達した所（推定の腕が相手の腕を大きく通り抜けた所） |
| 自重する腕が不自然にずれる・胴に食い込む | `arm_collision.mode` を反対の腕（`right` / `left`）にする。ずれが大きすぎるなら `arm_collision.max_deg` を小さく、腕どうしが離れすぎるなら `arm_collision.radius_scale` を小さく |
| 自重する腕のひじの曲がり方が不自然に変わる | `arm_collision.elbow_max_deg` を小さく（15 など。残りは肩で離す）するか、`arm_collision.elbow: false` で肩だけで離す |
| カメラから見て、自重する腕が動画の位置から上下・左右にずれる | `arm_collision.depth_cost` を小さく（0.3 など）して前後へのずらしをさらに優先する。横から見て腕が前後に離れすぎる・胴に食い込むなら大きく（1 で以前と同じ） |
| 全身が震える／動きが鈍い | `jitter.one_euro.groups.*.min_cutoff` を小さく／大きく |
| 腕・脚・体の向きが数フレームだけ飛ぶ（外れが残る） | `outliers.png`（その所の度合いが 1 未満なら見逃し）とログの `[1b]`。`outliers.pose.threshold` を小さく（5 など）・`outliers.pose.min_m` を小さく |
| 本当の速い動き（キメの一瞬の動き）がなまる | `outliers.png` でその所が置き換えられていたら `outliers.pose.threshold` を大きく（8 など）。`outliers.enabled: false` で外れの除外をやめる |
| 人に持ち上げられる・壁や手すりを押す・カメラが動く動画で体の位置がおかしい | `outliers.gravity.enabled: false`（重心の加速度が重力と床からの力だけでは決まらない） |
| 腰・胸に当てた手が離れる・入り込む、胸の前で合わせた両手が交差する | `hand_reach.png` と `diagnostics.json` の `info.hand_reach`（`ratio`: 胴の寸法の比、`frames`: 位置を保ったフレーム数）。手が胴から離れていると位置を保たないので `hand_reach.far_m` を大きく。ひじが伸び気味の腕なら `hand_reach.bend_deg` を小さく。補正が足りない（`hand_reach.png` の赤い破線）なら `hand_reach.max_deg` を大きく |
| 下ろした腕・前に出した腕の向きが動画と違う | `hand_reach.near_m`・`far_m` を小さく（胴に近い手だけ位置を保つ）。`hand_reach.enabled: false` で回転のコピーに戻る |
| 胸・顔に当てた手が揺れる・浮く | `jitter.hand_position.min_cutoff` を小さく（手首の位置の軌跡を強くならす）。手が止まっていると判定する速さは `jitter.hand_position.speed_m_per_s` |
| 袖・前腕がひじ・手首の所でねじれてつぶれる | PMX に `腕捩`・`手捩` があるか、ログの `[10] 捩りボーン` を確認（無い・つながりが違うモデルでは使えない）。`twist.enabled: false` で元の入れ方（ひねりを腕・ひじ・手首に入れる）に戻せる |

補足:

* One Euro フィルタはオフライン処理なので、順方向と逆方向の結果を平均して遅れを打ち消しています（`zero_phase`）。
  両端は点対称に延長してから掛けるので、一定速度で動いている区間の端にも加速度が出ません
* 奥行きの再構成（ステージ6b）は、骨盤の奥行きを「接地中の足首の奥行きが一定」「推定の奥行きから大きく離れない」
  「前後の加速度が小さい」の重み付き最小二乗で求め直し、体全体を奥行きの軸（カメラの光軸）に沿って平行移動します。
  足首→骨盤の相対位置は、ステージ2で平滑化する前の姿勢から求めます（平滑化した姿勢では遊脚の速い動きが接地の前後に
  混ざって床に着いた足首が前へずれ、1 歩ごとに歩いた距離が数 cm 短くなるため）
* 前後の傾きの補正（ステージ6c）は、体の縦のライン（骨盤→首など）ではなく、「全身の重心は、数秒の平均では
  接地している足の上にある」という条件を使います。縦のラインをフレームごとに鉛直にすると、お辞儀など本当の前傾まで
  消えますが、本当の前傾では腰が後ろへ引かれて重心は足の上に残るので、この条件なら消えません。速い動き（歩行で
  重心が支持脚の前後に 30cm 以上離れる）も、重心と足圧中心の差は重心の加速度に比例して時間平均では打ち消し合うので、
  数秒の窓（`lean.window_sec`）で平均した差を 0 にします。重心は関節の位置と体の部位の質量比（de Leva 1996）から、
  片足接地はその足の支持点の中心、両足接地は両足の支持点の範囲（その間ならどこでもよい）、接地判定から漏れた短い区間は
  前後の支持点をつないだ点と比べます。補正角は格子の上で探します。補正はカメラの奥行き方向だけで（左右の傾きは
  画像に写るので正しい）、足首から下は動かさず、骨盤から上の大域回転を回して骨盤を足の上へ平行移動します
* 床の傾きは、同じフレーム内の接地点どうしを結ぶベクトル（かかと→つま先、左足→右足）が床と平行になるように
  求めます（`floor.tilt_method: vectors`）。単眼推定では体全体の位置がカメラの視線に沿ってずれるので、全フレームの
  接地点に 1 枚の平面を当てはめると、ずれで伸びた点群の向き（視線の傾き）を床の傾きと取り違えます
  （合成データでは、水平なカメラで 6〜10 度の傾きを誤って補正し、10 度の見下ろしを 4 度と推定していました）。
  ベクトルが 1 方向にしか無いとき（横向きのまま横へ歩く等）は、接地中の足裏の向きを弱い重みで加えて補います
* 接地の拘束（ステージ6a）は、接地している足（両足とも接地していれば低いほう。接地している足が無ければ両足の最下点）が
  床に着くように体全体を上下に平行移動します。遊脚・床を擦って動かしている足の足先が、向きの推定のぶれで床の下に
  見えても、体全体は上下しません。両足が床から離れている
  区間は、物理的にジャンプとしてありうるもの（長さ 0.15〜0.6 秒で、骨盤が重力加速度に合う放物線を描く）だけを
  ジャンプとして残し、それ以外は推定のずれ・揺れとみなして床に戻します。足首の向きの推定の揺れで足先だけが
  上がって見える区間までジャンプとして残すと、その間は全身が数 cm 浮き、接地判定からも漏れます。
  接地中の足ＩＫの高さも、足裏が床に着く高さでロックします（`foot_ik.snap_to_floor`）
* 接地中に、かかとを上げてつま先だけが着いている所・かかとだけが着いている所・つま先やかかとを軸に足を回す所は、
  床に着いている点（モデルの足の形のかかと・つま先）を固定し、足の回転は推定のまま動かします（`foot_ik.pivot`）。
  接地区間全体を 1 つの足首の位置・回転で固定すると、蹴り出しのかかと上げやピボットが接地中は消え、区間の終わりで
  一気に戻るためです。足裏全体が着いている所は従来どおり固定します（接地中ずっと足裏全体なら、従来とまったく同じ値）。
  判定は、かかと（つま先）が足の最も低い点より 5cm 以上上がっているか、足の向きが速く（90 度/秒以上）大きく（20 度以上）
  回ったかで、足の位置の速さ（体全体のぶれが乗る）は使いません。`vmd_diag/diagnostics.json` の
  `info.foot_ik.pivot_frames` に、つま先だけ・かかとだけを固定したフレーム数が出ます
* 腕は関節ごとの One Euro のほかに、手首が胸に対して遅く動いている（止まっている）間だけ、手首の位置の軌跡を
  平滑化したものに肩・ひじを合わせます（`jitter.hand_position`）。関節ごとの平滑化では、ひじを張る・肩をすくめるなど
  関節の動きが手首では打ち消し合うときに、打ち消し合いが崩れて止まっているはずの手首が揺れるためです。
  速く動く手に位置の平滑化を掛けると、関節ごとの平滑化より強く掛かって手先の動きが小さくなる（合成データで誤差が
  15〜60% 増える）ので、速い間は関節ごとの平滑化のままにします
* 捩りボーン（腕捩・手捩）のあるモデルでは、腕・ひじ・手首のひねり（骨の軸まわりの回転）を swing-twist 分解で
  取り出して捩りボーンに入れます（`twist.py`）。腕捩1〜3・手捩1〜3（回転付与）が上腕・前腕に沿ってひねりを分けるので、
  関節の所で袖・前腕のメッシュがつぶれません。大域回転は変えません。ひねりの角は時間方向に連続につなぐので、手のひらを
  上に向ける（約 180 度）動きでも逆向きに跳ねず、捩りボーンに入れるのは ±160 度までです（残りは元のボーンへ）
* 届く高さへのクランプでは、ガウシアンのカーネルを移動最小値の窓の半分で打ち切っています。
  こうすると平滑化後の補正量がどのフレームでも必要量以上になり、クランプ後に脚が伸び切るフレームが残りません
* 回転の補正（初期姿勢補正方式の C）は、SMPL と MMD モデルの初期姿勢が本当に違う所（腕の T ポーズと A ポーズ）
  だけに掛けます。関節の位置を結んだ向きを合わせる方法は、両者で関節の置き方が同じ所でしか使えないためです
  （SMPL の頭の関節は首より 5cm ほど前にあり、そのまま合わせると首が前に倒れて顎を突き出した姿勢になります。
  肩はすくみ、足裏はつま先が上がる向きに傾きます）。体幹・首・頭は「上向き＝鉛直」として左右のねじれだけ、
  肩は補正なし、手首は前腕と同じ補正、足ＩＫはつま先の左右の向き（SMPL の初期姿勢は約 15 度外向き）だけ合わせます。
  `retarget.*` の設定で、関節の位置から求める方法（vmd.md の記述どおり）に戻せます
* 補間パラメータ 64 バイトの配置は MMD Tools（blender_mmd_tools）の実装で確認したものです（`vmd.py` の先頭に記載）

```bash
python -m pytest nlf2vmd/tests
```

合成データ（`synthetic.py`: 支持脚が床に固定された歩行、簡易体モデル）で、vmd.md の自動テスト
（フィルタ・接地判定・足ＩＫ・センター・VMD の読み戻し・座標変換）と、単眼推定のような奥行きのぶれを加えても
接地中の足が前後に滑らないこと、高い位置・見下ろしのカメラで視線に沿った距離のずれを加えても床の傾きを正しく求め、
両足が浮いたままにならないこと（ジャンプは残ること）、
体全体がカメラの前後に 10 度傾いた推定を起こすこと（お辞儀の前傾と、画像の左右方向の傾きは残すこと）、回転の補正（中立姿勢の SMPL は MMD でも中立姿勢になる・
接地中の足裏が床と平行）、PMX・体モデル・設定の読み込みを確認します。
腕どうしの貫通の防止は、胸の前で両腕を交差させた合成の動きで、自重する側の腕・ひじボーンだけが変わって重なりが無くなること、
推定の前腕が相手の前腕を通り抜けても自重する腕は来た側に留まること、上限を超えるときは少しずつ通り抜けること、
奥行き優先（`depth_cost`）で前後へずらすこと、ひじも曲げると手首・手の先の画像面内の動きが減ること、ひじをまっすぐより先へ
伸ばさないこと、補正した回転から求めた腕の位置（VMD に入る姿勢）で重なりが無いこと、
PMX のメッシュから腕の太さと手の長さを求めることを確認します。
検出できなかったフレームが床・接地・奥行き・ジャンプの判定に使われないこと、
外れフレームの除外で、揺れのある歩行・ジャンプ・速い腕の動き・速い回転は置き換えず、数フレームの腕・脚・体の向き・骨盤の上下と
奥行きの外れ（先頭・末尾を含む）はちょうどそのフレームだけ置き換えて正解に近づけること、
手首の向きの補正で、ROI の戻し方が往復で一致し、ひねり違えた手首が正しい向きに戻り、信頼できない検出は使わないこと、
腕・指と体の接触で、PMX の剛体の読み込みと分類、指の各節のカプセル、指先・前腕が胸に入る姿勢を主に手首・ひじで離すこと、
胸を通り抜ける推定でも手が胸の前に留まること、指の形を入れて解き直すことを確認します。
遊脚の足先が床の下に見えても体全体が上下しないこと、胸の前に置いた手は関節が動いても揺れにくく速く動く手は変わらないこと、
腕・ひじ・手首のひねりを腕捩・手捩へ移しても腕の姿勢が変わらず、手のひらを返す動きで捩りボーンが跳ねないことを確認します。

キー（切り替えの始まりと終わり・イーズの補間）と体の動きの VMD との合成を確認します。
