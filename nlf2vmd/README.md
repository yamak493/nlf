# nlf2vmd — NLF のモーションを MMD 用 VMD に変換する

NLF（[mp4_to_mannequin_ja.ipynb](../mp4_to_mannequin_ja.ipynb)）で抽出した SMPL のモーションを、
MikuMikuDance / MikuMikuMoving 用の VMD に変換します。仕様は [vmd.md](../vmd.md) です。

* 脚は**足ＩＫの位置キー**、体の移動は**センター（水平）／グルーブ（上下）**、上半身と腕は**回転キー**で出力します
* 接地中の足はロックし（足滑り 0）、床に埋まらないようにし、脚が伸び切らない高さまでセンターを下げます
* 単眼推定でぶれやすい奥行き（カメラの前後）は、接地している足から骨盤の奥行きを求め直します（Z 方向の足滑りを防ぐ）
* 奥行きのずれがカメラの高さ・見下ろし角のせいで上下のずれにもなり、両足が長く宙に浮いたままになる状態は、
  体全体を上下に平行移動して床に戻します（滞空 0.6 秒以下のジャンプはそのまま残します）
* 単眼推定ではカメラの前後に傾く角度がほとんど決まらず、足が床に着いたまま体全体が前後に傾くので、
  全身の重心が接地している足の上に来るように骨盤から上を起こします（重心が足の上に残るお辞儀・前傾はそのまま残します）
* 処理前後の評価指標（JSON）と、判定の妥当性を確認するグラフ（PNG）を毎回出力します
* GPU も SMPL の公式ファイルも不要です（体モデルは NLF の TorchScript から書き出したものを使います）

## 使い方

### ノートブックから

`mp4_to_mannequin_ja.ipynb` のセル 14 を実行すると `nlf_mannequin/motion.vmd` ができます。
同じフォルダに、変換の入力 `motion_for_vmd.npz` と体モデル `smpl_body_model.npz` も保存されます。

### コマンドラインから

必要なもの: Python 3.9 以上、`numpy` `scipy` `pyyaml` `matplotlib`（グラフを出す場合）。

```bash
# ノートブックが保存した入力と体モデルから変換（体モデルは同じフォルダにあれば自動で使われます）
python -m nlf2vmd motion_for_vmd.npz -o motion.vmd --pmx モデル.pmx

# 設定を 1 項目ずつ変える
python -m nlf2vmd motion_for_vmd.npz --pmx モデル.pmx --set center.mode=B --set scale.depth_scale=0.5

# 設定ファイルで変える（default_config.yaml をコピーして、変えたい項目だけ残す）
python -m nlf2vmd --dump-config my_config.yaml
python -m nlf2vmd motion_for_vmd.npz --pmx モデル.pmx --config my_config.yaml

# 入力なしで動作確認（合成の歩行データと簡易体モデル）
python -m nlf2vmd --demo -o demo.vmd
```

### Python から

```python
from nlf2vmd import convert

result = convert('motion_for_vmd.npz', 'motion.vmd', pmx='モデル.pmx',
                 overrides=['center.mode=B'])
print(result.metrics['foot_slide_cm_per_frame'])   # {'before': ..., 'after': ...}
```

`convert` の入力は npz のパスか、同じキーを持つ dict です。

| キー | 形 | 内容 |
|---|---|---|
| `pose` | (T, 24, 3) | SMPL の関節回転（回転ベクトル）。(T, 24, 4) のクォータニオン、(T, 24, 3, 3) の回転行列も可。先頭に人物の次元があれば `input.person_index` の 1 人を使う |
| `betas` | (T, 10) か (10,) | 体型。フレーム毎なら中央値で 1 つに固定 |
| `trans` | (T, 3) | SMPL の移動量 [m] |
| `fps` | スカラー | |
| `coord_system` | 任意 | `camera`（NLF の出力: Y 下向き・Z 奥向き）か `yup`。無ければ `input.coords` の設定（既定 camera） |
| `valid` / `joints3d` | 任意 | 検出できたフレーム / 関節位置 [mm]（体モデルの自己検証に使う） |

体モデルは `--body-model`、入力 npz 内の `bm_*` キー、入力と同じフォルダの `smpl_body_model.npz`、
smplfitter（SMPL 公式ファイル）の順に探します。

## 出力

| MMD ボーン | キー | ソース |
|---|---|---|
| センター | 位置（X, Z） | 骨盤の水平位置（ステージ8） |
| グルーブ | 位置（Y） | 骨盤の高さ（ステージ8）。グルーブが無いモデルはセンターの Y |
| 下半身 / 上半身 / 上半身2 | 回転 | 骨盤(0) / 背骨(3, 6) / 背骨(9)。上半身2 が無いモデルは上半身に合成 |
| 首 / 頭 | 回転 | 首(12) / 頭(15) |
| 左右の肩・腕・ひじ・手首 | 回転 | 鎖骨(13, 14)・肩(16, 17)・肘(18, 19)・手首(20, 21) |
| 左足ＩＫ・右足ＩＫ | 位置＋回転 | 足首の位置と回転（ステージ7） |

足・ひざ・足首・つま先ＩＫ・捩りボーンにはキーを打ちません。キーは全フレームに打ちます（`vmd.thin_keys` で間引き可）。
PMX を指定しないときは、標準的な体格（身長 20 単位前後・A ポーズ）のボーン寸法で変換します。
**実際に使うモデルの PMX を指定するのがおすすめです**（脚長とボーンの向きをモデルから読みます）。

診断出力（既定: `<VMD 名>_diag/`）:

* `diagnostics.json` — 評価指標（処理前・処理後）、接地区間、床・スケール・警告などの情報、使った設定
* `contact.png` — 左右の足の高さ・水平速度と接地判定の帯
* `center.png` — センターの X・Y・Z の処理前後
* `depth.png` — 骨盤の奥行きの処理前後（接地している足から求め直した奥行き）と、入力の奥行き・横方向のぶれの大きさ
* `ground.png` — 両足の最下点の高さの処理前後と、接地の拘束による上下の補正量（ジャンプとして残した区間はオレンジの帯）
* `lean.png` — 足の支持点の中心から全身の重心への線の前後（カメラの奥行き方向）の傾きの処理前後と、掛けた補正角
* `reach_clamp.png` — 届く高さへのクランプの補正量
* `foot_ik_topview.png` — 足ＩＫの水平軌跡の上面図（接地点が点になっているか）

| 指標 | 定義 | 目標 |
|---|---|---|
| 足滑り | 接地区間内の足ＩＫの水平移動量の平均（cm/フレーム） | 0 |
| 埋まり | 足ＩＫの差分Yが0未満のフレーム数 | 0 |
| 浮き | 両足の最下点が接地終了の高さより上にいる状態が、`ground.max_flight_sec`（0.6 秒）より長く続くフレーム数 | 0 |
| 短い浮き | 両足とも接地区間の外で、ジャンプとして残した区間でもないのに、出力の両足の足裏が床から 2cm より上にあるフレーム数 | 0 に近い |
| センターの震え | センター・グルーブ位置の加速度の絶対値の平均（軸別、cm/フレーム²） | 処理前より大幅に減少 |
| 姿勢の震え | 各関節の角加速度の平均（グループ別、deg/s²） | 処理前より減少 |
| 脚の伸び切り | 股関節から足ＩＫまでの距離が脚長の98%を超えるフレーム数 | 0 |
| 接地切り替え回数 | 足ごとの接地区間の数 | 目視との整合を確認 |
| 床付近の足の動き | 足が床付近にあるときの足ＩＫの移動量の平均（X, Z 別、cm/フレーム） | Z（奥行き）が X と同程度まで減少 |
| 前後の傾き | 足の支持点の中心から全身の重心への線の、カメラの奥行き方向の傾きの中央値（度） | 0 に近い |

## 設定

既定値はすべて [default_config.yaml](default_config.yaml) にあり（説明付き）、設定ファイルか `--set` で上書きします。
長さのしきい値はメートルで書き、ステージ5以降は内部でスケール係数を掛けて使います。
存在しない項目を書くとエラーになります（タイプミス防止）。

MMD で見て問題があったときの調整の目安:

| 症状 | 調整する設定 |
|---|---|
| 体が後ろを向く・進行方向が逆 | `floor.flip_facing: true` |
| 足が滑る・接地のタイミングがずれる | `contact.png` を見て `contact.*` のしきい値 |
| 足が前後（Z）にだけ滑る | `depth.png` と `diagnostics.json` の `info.depth.root_jitter_cm`（奥行きのぶれ）を確認。`depth.contact_sigma_m` を小さく・`depth.prior_sigma_m` を大きく（接地足をより優先） |
| 歩いた距離（前後）が動画と合わない | `depth.prior_sigma_m` を小さく（推定された奥行きの移動に近づける） |
| 足が浮く・埋まる | `ground.png`（オレンジ = ジャンプとして残した区間、赤 = 短い浮き）と `diagnostics.json` の `info.ground.jumps_sec`（ジャンプとして残した区間 [秒]。動画のジャンプと合っているか）・`info.floor`（`tilt_deg` がカメラの見下ろし角と合っているか） |
| 本物のジャンプが床に押し付けられる | `info.ground.jumps_sec` に入っていなければ `ground.flight_accel_g` の下限を小さく（0.3 など）、`ground.min_flight_sec` を小さく。0.6 秒より長い滞空なら `ground.max_flight_sec` を大きく |
| ジャンプしていないのに体が浮く（オレンジの帯が多い） | `ground.flight_accel_g` の下限を大きく（0.7 など） |
| 座る・寝転ぶ動きでお尻が床に埋まる | `ground.enabled: false`（両足が長く床から離れる動きは浮きとみなして床に戻すため） |
| 体全体が前後（カメラの奥行き方向）に傾いている | `lean.png`（重心の傾きの線が 0 付近か）と `diagnostics.json` の `info.lean.correction_deg`（補正角）。補正がゆっくり揺れるなら `lean.window_sec` を大きく（0 でシーケンス全体で 1 つの角度） |
| 座る・寄りかかる・重い物を持つ動きで上半身が不自然に起きる | `lean.enabled: false`（重心が足の上に無い動きなので） |
| 体全体が左右に傾いている・足の裏が床と平行でない | `info.floor` の `tilt_deg`・`tilt_mode`。うまくいかなければ `floor.tilt_method: plane`（従来の方法）や `floor.align_tilt: false` と比べる |
| センターが前後にふらつく | `depth.accel_sigma_m_per_s2` を小さく、`center.axis_one_euro.z.min_cutoff` を小さく、`center.mode: B`（`scale.depth_scale` は、接地中の前後の動きを足から求め直すので効きが弱い） |
| 膝が伸び切る・暴れる | `center.reach_ratio`（0.95 など） |
| 足先の向きが変わらない | PMX に `左つま先ＩＫ` / `右つま先ＩＫ` があるか確認（足ＩＫの回転はつま先ＩＫを通して足首に伝わる） |
| 全身が震える／動きが鈍い | `jitter.one_euro.groups.*.min_cutoff` を小さく／大きく |

## 処理の構成

| ステージ | モジュール |
|---|---|
| 1. 読み込み・正規化 | `motion_io.py` |
| 2. 姿勢のジッター制御 | `jitter.py`（フィルタは `filters.py`、クォータニオンは `quat.py`） |
| 3. FK で関節位置を算出 | `body_model.py` |
| 4. 床面推定と定数オフセット | `floor.py` |
| 5. MMD スケールへ変換 | `pipeline.py`（`apply_scale`）、モデルの寸法は `pmx.py` / `skeleton.py` |
| 6a. 接地の拘束 | `ground.py` |
| 6. 接地判定 | `contact.py`（速度から奥行きのぶれを除くのは `depth.py`） |
| 6c. 前後の傾きの補正 | `lean.py` |
| 6b. 奥行きの再構成 | `depth.py` |
| 7. 足ＩＫ生成 | `foot_ik.py` |
| 8. センター安定化 | `center.py` |
| 9. 上半身の回転リターゲット | `retarget.py` |
| 10. VMD 書き出しと診断出力 | `vmd.py`、`diagnostics.py` |

全体の順番は `pipeline.py` の `convert` にあります。順番は入れ替えないでください（vmd.md 参照）。

補足:

* One Euro フィルタはオフライン処理なので、順方向と逆方向の結果を平均して遅れを打ち消しています（`zero_phase`）。
  両端は点対称に延長してから掛けるので、一定速度で動いている区間の端にも加速度が出ません
* 奥行きの再構成（ステージ6b）は、骨盤の奥行きを「接地中の足首の奥行きが一定」「推定の奥行きから大きく離れない」
  「前後の加速度が小さい」の重み付き最小二乗で求め直し、体全体を奥行きの軸（カメラの光軸）に沿って平行移動します。
  足首→骨盤の相対位置は、ステージ2で平滑化する前の姿勢から求めます（平滑化した姿勢では遊脚の速い動きが接地の前後に
  混ざって床に着いた足首が前へずれ、1 歩ごとに歩いた距離が数 cm 短くなるため）
* 前後の傾きの補正（ステージ6c）は、体の縦のライン（骨盤→首など）ではなく、「全身の重心は、数秒の平均では
  接地している足の上にある」という条件を使います。縦のラインをフレームごとに鉛直にすると、お辞儀など本当の前傾まで
  消えますが、本当の前傾では腰が後ろへ引かれて重心は足の上に残るので、この条件なら消えません。速い動き（歩行で
  重心が支持脚の前後に 30cm 以上離れる）も、重心と足圧中心の差は重心の加速度に比例して時間平均では打ち消し合うので、
  数秒の窓（`lean.window_sec`）で平均した差を 0 にします。重心は関節の位置と体の部位の質量比（de Leva 1996）から、
  片足接地はその足の支持点の中心、両足接地は両足の支持点の範囲（その間ならどこでもよい）、接地判定から漏れた短い区間は
  前後の支持点をつないだ点と比べます。補正角は格子の上で探します。補正はカメラの奥行き方向だけで（左右の傾きは
  画像に写るので正しい）、足首から下は動かさず、骨盤から上の大域回転を回して骨盤を足の上へ平行移動します
* 床の傾きは、同じフレーム内の接地点どうしを結ぶベクトル（かかと→つま先、左足→右足）が床と平行になるように
  求めます（`floor.tilt_method: vectors`）。単眼推定では体全体の位置がカメラの視線に沿ってずれるので、全フレームの
  接地点に 1 枚の平面を当てはめると、ずれで伸びた点群の向き（視線の傾き）を床の傾きと取り違えます
  （合成データでは、水平なカメラで 6〜10 度の傾きを誤って補正し、10 度の見下ろしを 4 度と推定していました）。
  ベクトルが 1 方向にしか無いとき（横向きのまま横へ歩く等）は、接地中の足裏の向きを弱い重みで加えて補います
* 接地の拘束（ステージ6a）は、両足の最下点が床に着くように体全体を上下に平行移動します。両足が床から離れている
  区間は、物理的にジャンプとしてありうるもの（長さ 0.15〜0.6 秒で、骨盤が重力加速度に合う放物線を描く）だけを
  ジャンプとして残し、それ以外は推定のずれ・揺れとみなして床に戻します。足首の向きの推定の揺れで足先だけが
  上がって見える区間までジャンプとして残すと、その間は全身が数 cm 浮き、接地判定からも漏れます。
  接地中の足ＩＫの高さも、足裏が床に着く高さでロックします（`foot_ik.snap_to_floor`）
* 届く高さへのクランプでは、ガウシアンのカーネルを移動最小値の窓の半分で打ち切っています。
  こうすると平滑化後の補正量がどのフレームでも必要量以上になり、クランプ後に脚が伸び切るフレームが残りません
* 回転の補正（初期姿勢補正方式の C）は、SMPL と MMD モデルの初期姿勢が本当に違う所（腕の T ポーズと A ポーズ）
  だけに掛けます。関節の位置を結んだ向きを合わせる方法は、両者で関節の置き方が同じ所でしか使えないためです
  （SMPL の頭の関節は首より 5cm ほど前にあり、そのまま合わせると首が前に倒れて顎を突き出した姿勢になります。
  肩はすくみ、足裏はつま先が上がる向きに傾きます）。体幹・首・頭は「上向き＝鉛直」として左右のねじれだけ、
  肩は補正なし、手首は前腕と同じ補正、足ＩＫはつま先の左右の向き（SMPL の初期姿勢は約 15 度外向き）だけ合わせます。
  `retarget.*` の設定で、関節の位置から求める方法（vmd.md の記述どおり）に戻せます
* 補間パラメータ 64 バイトの配置は MMD Tools（blender_mmd_tools）の実装で確認したものです（`vmd.py` の先頭に記載）

## テスト

```bash
python -m pytest nlf2vmd/tests
```

合成データ（`synthetic.py`: 支持脚が床に固定された歩行、簡易体モデル）で、vmd.md の自動テスト
（フィルタ・接地判定・足ＩＫ・センター・VMD の読み戻し・座標変換）と、単眼推定のような奥行きのぶれを加えても
接地中の足が前後に滑らないこと、高い位置・見下ろしのカメラで視線に沿った距離のずれを加えても床の傾きを正しく求め、
両足が浮いたままにならないこと（ジャンプは残ること）、
体全体がカメラの前後に 10 度傾いた推定を起こすこと（お辞儀の前傾と、画像の左右方向の傾きは残すこと）、回転の補正（中立姿勢の SMPL は MMD でも中立姿勢になる・
接地中の足裏が床と平行）、PMX・体モデル・設定の読み込みを確認します。
MMD での見た目の確認（足の滑り・埋まり・浮き・膝の暴れ・全身の震え）は手動で行ってください。
